# ADR-0020: bounded remote disaggregated shuffle v1

Status: Accepted and implemented, 2026-10-28; COMPLETE_BOUNDED_REMOTE_V1. Review remediation and source-bound local revalidation are recorded in the Phase 13 report and remediation evidence.

## Authority and boundary

The user's execution request authorizes Phase 13 after independent G0 proof.
G0 passed on `474f8c92ff13ffb59c63d8fd2edd3be4ce6019bb`, with a fresh
feature-matched build, the complete operations suite and an additional independent
running/staged compatibility-drift witness. See the source-bound report/evidence.
This refines architecture §§7,9–10,12,15,17,22–24,27–31 and preserves INV1–10.
Phase 10 physical elasticity and Phase 12 production HA remain incomplete.

`remote-s3` is a default-off Cargo feature of `ade-distributed`. A dedicated
experimental `remote_object` aggregate executor, coordinator API and `ade-remote` entrypoint execute only the
original static GroupBySum shape over a validated physical IR/catalog. The
existing worker binary has a separate one-shot `--remote-stage` pipe protocol.
Native operators, hash1 distribution, bounded IPC decoder, final merge and
attempt-safe gather are reused. No frontend/DataFusion dependency enters core.
Legacy ADETCP12/ADEOPS01, exchange2, input/benchmark/result1 stay unchanged.
All-feature builds include the new feature in the native compatibility digest;
existing operations registrations therefore require their matching binaries.

Only 2–4 original logical producer IDs and static hash destinations are admitted.
The producer cohort exits and is reaped before a fresh reader cohort starts.
Reader width can be 1..N, handling a predeclared disjoint modulo assignment of
the SAME N final partitions sequentially. This is stage-boundary independent
compute width, not live membership changes, in-flight replacement or migration.
Joins, projections beyond the original grouped sum/count, leased/static_projected,
adaptive operators/topology, automatic recovery, remote inputs, general SQL/DAGs,
managed operations integration, external sinks and HA are refused/deferred.
This is not a reusable remote exchange plugin in the existing common exchange
selector. Reader-width variation across predeclared fresh processes is not
physical worker elasticity; both remain tracked roadmap debt.

## Actors, identities and trust

Trusted local Unix operator, coordinator and worker executable; private canonical
scratch; immutable local Parquet sources; untrusted object contents/availability.
An object service cannot supply an eligibility hash to the coordinator. The
coordinator pins producer replies and the global manifest hash independently.
Integrity hashes do not authenticate a malicious coordinator or credential owner.
Before effects, validate IR, exact source/schema/row/byte inventory, configuration,
source paths, resource bounds and credentials. Reverify sources before/after each
producer and before manifest promotion and successful result return. File checks
retain Phase 11's immutable-source assumption, not transactional isolation.

Identity is `(job, execution UUID, attempt=0, hash1/static topology digest,
plan/source/config/store digest, logical transfer, segment sequence)`.
Logical transfer remains `(job, exchange0, destination, original producer)`.
One execution UUID is generated by the coordinator and never reused. This path
has no retry/adoption API. A fresh invocation gets a new UUID, even for the same
logical job. Readers receive epoch1, exact assigned partitions and their fresh
boot UUID via a versioned, single-use pipe grant. They reject other epochs,
boots, layouts, stores, manifest hashes and attempts. Old processes have no
control listener or capability to claim another grant. All children are owned,
killed and reaped on cancellation/error; uncertain teardown cannot yield output.

## Storage publication protocol

Keys derive only from validated components:
`PREFIX/remote-v1/EXECUTION/attempt-0/p-P/from-W/segment-S.arrow`,
`.../p-P/from-W/TERMINAL.json`, and `.../MANIFEST.json`.
Prefix is one bounded ASCII component, UUID is canonical nonnil lowercase,
IDs are validated integers. No user-provided key or LIST determines completeness.

| Step | Preconditions / visibility |
|---|---|
| Segment PUT | Bounded single IPC batch; conditional create (`If-None-Match: *`); reserve bytes/object/request first |
| Verification | HEAD exact size, bounded GET, exact bytes/BLAKE3; failure aborts, never local fallback |
| Transfer terminal | After all its segment verifications and producer source postflight; immutable JSON includes exact sequence/count/bytes/hash descriptors and original transfer hash chain; empty terminals explicit |
| Global manifest | Only after every producer succeeded, exited/reaped, scratch removed, all N×N terminal references verified and sources rechecked; conditional create then HEAD/GET verification |
| Reader grant | Exact independently pinned global-manifest hash and new boot/epoch/partition assignment; global manifest alone cannot authorize a new run |
| Consumption | Validate entire expected terminal set and descriptor bounds before execution; lazily fetch each assigned segment, verify bytes/hash/schema/row count/hash owner and terminal chain before successful final completion |
| Result | All N final terminals, hashes, conservation, output limits and source postflight pass; then return batches. Failed gather remains private and is discarded |

There is no object rename or multi-object transaction. Provider must implement
conditional create and read-after-successful-PUT visibility. A capability probe
must observe a rejected divergent second create and unchanged first object.
Unsupported behavior refuses. Duplicate creation (even identical) is refused;
there is no ambiguous write retry. HEAD/GET never accepts missing or oversized
objects. Byte hashes and a pinned manifest detect malicious rewrites, regardless
of ETag behavior. A backend can deny availability, not manufacture partial success.
Versioned buckets may retain historical versions; physical reclamation of those
versions is the operator's responsibility, not this exact-key DELETE API.

`CAPABILITY` is a bounded create/HEAD/GET/delete probe inside the same private
namespace; it never establishes transfer completeness. Per-transfer terminals alone are provisional. A late PUT after an aborted
request may leave an orphan; it cannot produce a coordinator-pinned global
eligibility proof or a new reader grant. Even an ambiguously completed global
PUT is never adopted after error/cancellation. No job output is published by
this protocol. The API returns a fully verified bounded result; its CLI emits
success only after the full run. It does not extend Phase 12's sink contract.

## Bounds, I/O and cancellation

Default/max limits are explicit in `remote::Limits`: source limits inherit IR1
(64 files, 1m rows, 64MiB physical source, 16MiB decoded row group); task state
32MiB with operator spill disabled; one 1024-row/1MiB encoded frame per request;
bounded manifest/control messages; per-producer segment/byte/object/request caps;
finite total stage <=120s; per-request <=5s; one request at a time per actor,
at most four worker actors. Gather uses the shared cumulative write budget;
result collection uses existing row/Arrow-accounted limits. Metadata, frame,
source decoder, task and network transients are separate domains, not RSS caps.
All counters use checked arithmetic. Reserved uncertain write bytes are not
refunded. Each role's limits multiply by the explicitly bounded cohort width.

The public S3 provider uses explicit endpoint/bucket/region/prefix, signed
requests and environment credentials loaded at creation, with provider retries
disabled. A public custom HTTP connector disables redirects and ambient proxies,
limits each response body (including SDK error XML) to1MiB and cumulative admitted
HTTP response bodies to64MiB per actor, and counts actual HTTP requests/body bytes. An explicit bounded read retry may occur for generic provider/transport response errors;
all attempts count against request/deadline budgets. The public provider error
classification permits a bounded repeat for Generic provider/transport response
errors on reads; known permanent variants, wrong size/hash/schema and writes do
not retry. Unknown Generic read failures may therefore receive one extra read,
never relaxed verification or an ambiguous write retry. Writes never retry after
ambiguity. Each operation races cancellation and absolute deadline in an owned
Tokio runtime. No detached per-operation threads, multipart uploads or unbounded
background queues. A failed client is poisoned and cannot publish more data.
Process cancellation kills/reaps children; service-side operations already
received may still complete and are treated as residual orphan debt.

TLS is required by default. Explicit dev HTTP permits literal loopback IPs only.
URLs with user info/query/fragment/path or invalid bucket/prefix refuse. No
anonymous credentials, ambient metadata fallback, public ACL, service deployment
or credential serialization. Provider errors are mapped to fixed redacted
messages. Test service credentials are throwaway fixture values. Loopback Moto
is an S3 API fixture with no production authentication/durability assertion.

## Failure windows and cleanup

Before/mid segment PUT, before terminal, after a subset of terminals, producer
crash or source drift: no global eligibility and no output. After global manifest
and producer exit: fresh readers can succeed from remote data alone. Reader
crash, wrong data, lost store, timeout, duplicate finalization or cancellation:
cancel/reap the cohort and discard gather; no result. Old or late actors never
join another execution's UUID/boot/grant. Whole coordinator loss is not recovered;
the namespace is an explicit manual orphan. No attempt replay is claimed.

Cleanup uses exact derived and verified keys, never LIST or bucket/prefix-wide
deletion. Default is dry-run. Applying cleanup requires an in-memory quiescence
capability produced only after the coordinator has reaped its consumers; a live
or failed/ambiguous run cannot yield that capability. Committed intermediates
remain until quiescence and explicit apply. Failed/crashed/late-write orphans
are preserved for the operator; inspect the recorded UUID, fence all actors,
wait for provider operations/lifecycle retention, then remove only validated
private keys. No TTL/background GC race or bucket lifecycle changes are hidden.

## Observation and required evidence

Record actual PUT/HEAD/GET/DELETE attempts, payload bytes, retries and operation
elapsed time, role/stage wall time, boot/PID/scratch/execution/source identity,
segment and terminal counts. Service request logs independently corroborate
network calls. Placement and integer nano-USD request/byte/egress/capacity rates
are CONFIGURED; counters/latency are MEASURED; there is no PROVIDER_BILLED value.
The receipt's existing `estimated_nano_usd` is an execution pre-cleanup proxy;
it excludes storage retention. Its data-byte rates apply to attempted transfer
bytes and do not report retained occupancy. A post-cleanup lifecycle proxy adds
successful delete counters and the exact verified retained bytes (segments,
terminals and global manifest) multiplied by the configured assumed retention
duration. A failed/partial cleanup has no complete lifecycle proxy. Checked
deterministic arithmetic fails on overflow. No policy automatically
chooses remote storage. Egress charges are configured estimates, not inferred
from locality labels. All same-data 2/4-worker balanced/skew local/remote samples
are retained with their methodology and overhead; no required speedup threshold.

Completion requires a real separate S3-compatible service, exact independent
oracle comparisons, fresh-reader boot/scratch after producer process exit,
failure/bounds/cleanup proofs, prior-path regressions and source-bound release
evidence. A filesystem mock or one-blob read cannot satisfy those obligations.
Repository-only reviewers must be told when raw local evidence artifacts are not
available to them; the tracked remediation summary names that access limit.
