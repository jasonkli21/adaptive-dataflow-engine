## 1. Executive assessment

The implementation does carry the research thesis into executable mechanisms. The local pull engine spills blocking state. Static distributed jobs use a common exchange with several retention modes. Single-final recovery uses replay or verified retained copies inside its documented failure envelope. The newer paths include finite pinned incremental/iterative runtimes, a local committed streaming prefix, and cross-job prefix reuse through actual native scan/filter materialization and actual native suffix execution. The adaptive mechanisms have different owners and qualifications. Their local campaign archives cannot establish present-day behavior of other modes or runtimes.

Three findings deserve priority.

1. **Fix native ordered LIMIT admission (ADE-IR-001, P1, observed).** A v1 projection can relabel an ordinary UInt64 column as the original `row_id`. On an identical, validated plan and pinned 513-row file, a 64 KiB spill run returned `value_i64=512` and a 256 MiB in-memory run returned `value_i64=0`. Original source IDs were strictly increasing in both executions. The corresponding genuine-ID control returned 0 in both.
2. **Bind isolated benchmark children to the exact parent inputs (ADE-IR-002, P1, source-supported).** The parent verifies one spec and manifest and records their identities, while children independently reopen mutable paths without verifying membership or physical identity against that parent selection. Equal output and matched requested engine configuration leave a physical-layout or equivalent-workload substitution undetected. Keep the independent oracle and the public v1 result shape.
3. **Separate historical verification and current Phase 26 release acceptance (ADE-IR-003 and 004, P1).** The current detached verifier unconditionally requires remediation labels missing from the 308-event frozen archive it is documented to replay. The current release flag also verifies selected artifact properties without binding the exact checkout source-set and executable to exact-SHA hosted checks or requiring a favorable economic result. Keep historical, diagnostic-negative and current-release decisions explicit.

Additional risks include a gather abandonment/terminal race, expiry regression under cache clock rollback, inconsistent cache victim tie-breaking, gateway slow-reader retention, and repeated full-artifact verification per resource-manager chunk. These are source findings that need the targeted tests specified below. No P0 was established. The listed P1s block the affected correctness or qualification claim and do not imply the repository's validated static controls are unusable.

Current qualification should come from the additive support matrices and reports. Phase 10 remains bounded fixed-membership and partial, Phase 18 partial, Phase 20 pending independent reacceptance, and Phase 21/22/23/25/26 have active remediation/reacceptance debt. Phase 24 is `REMEDIATION_REQUIRED` in its current support matrix, distinct from its historically hosted-pending candidate. Phase 17's stronger claims are source-bound to its local lineage, verifier and original service proof. Current README wording gives Phase 21's historical complete disposition as current (ADE-IR-011).

## 3. Findings register

### ADE-IR-001 · P1 · confirmed · A — Projection can defeat the original sort tie-breaker

**Contract and trace.** Query guide rows 48–63 calls sorted LIMIT deterministic and requires original `key,row_id,value_i64`. `ade-physical/src/lib.rs:319–340` allows a positional projection to relabel any valid same-type column. `356–379` checks types and displayed names at Sort and a two-element ordering at LIMIT. Native preflight checks the immutable source's actual `row_id` in `ade-exec/src/physical.rs:71–75,180–190`. Lowering then passes the projected names at `247–269`. The proof and the consumed value can differ. The physical IR and Rust path are enough to reach it; no claim is made about ingress through every legal SQL string.

**Observed regression.** A harmless Parquet file with 513 rows, `key=0`, `row_id=0..512`, `value_i64=0..512`. Native plan Scan → Project [key as key, key as row_id, value_i64 as value_i64] → Sort by key and row_id → LIMIT 1. Same plan digest `20dc03ebe693ee866a0b33541c6cce49bd68ee92039183e870d007198af4b1a5` and source from the workspace-resolution probe. At 65,536 managed bytes, 5 sort runs and result 512. At 268,435,456 bytes, 0 runs and result 0. The genuine-ID pass-through control returns 0 with and without spill. The final run combines short trailing level before the long preceding level in `ade-exec/src/sort.rs:231–237`; ties favor the left input at `134–144`. The data is immutable and both executions pass exact preflight and postflight.

**Fix and proof.** Carry positional source lineage during physical validation of sort keys, or trace Sort's input ordinals backward through the admitted Filter/Project transforms and require the real original source column for key, row_id and value. Preserve legitimate reordering and pass-through aliases that restore original names, existing PlanV1 layout, existing source uniqueness check, and legacy LocalPlan direct-sort semantics. Regression through public PlanV1 deserialization and native execution uses both budgets and refuses the counterfeit ordering proof, while valid reordered key/row_id/value plans remain equal. Sorting ties by value would change the contract and leave false lineage metadata.

### ADE-IR-002 · P1 · high/source-supported · A — Child benchmark input identity can differ from recorded inputs

**Contract and trace.** AGENTS benchmark integrity and architecture §29 require source/dataset/workload evidence and comparable runs. `ade-bench/src/runner.rs:82–91,97–129,156–167,184–215` verifies parent inputs, passes path arguments, and checks engine and the repeated canonical output. `ade-bench/src/cli.rs:199–202,316–323` reloads the paths in each child, with full inspection disabled for the internal child command. `ade-bench/src/engine.rs:674–707` correctly measures the chosen native execution and computes an independent expected result for the inputs the child actually opened. A changed spec whose canonical output happens to match can pass by the same mechanism. The parent publishes only its first manifest and spec after the series. Exact starting Git build identity and full parent preflight help provenance but do not convey the parent selection to each child.

**Fix and proof.** Give the private launch path expected exact spec/manifest digests and enforce them before each child starts timing. Preserve direct child invocation and v1 wire/result fields using an additive optional internally supplied expectation or command-local binding. For full verification, explicitly define/require immutable file bytes across the run or check the exact inventory outside the measured region, measuring the warmup/cache effect of any additional I/O. A controlled fixture changes only exact physical layout while keeping oracle rows equal; parent must retain an invalid iteration and refuse comparison. Cover unchanged full/manifest mode, execution outside child orchestration, and legacy result loading. Also align `result.rs:108–137` with parent checks for both fingerprint and row count; offline result validation currently verifies only the same nonempty fingerprint across iterations. Do not add signed-attestation claims to ordinary unsigned v1 results.

### ADE-IR-005 · P2 · high/source-supported · B — Gather abandonment and terminal acceptance lack one linearization point

**Contract and trace.** ADR-0013 §Gather commit refuses replacement after an already validated old terminal and quarantines the failed original store. `ade-distributed/src/gather.rs:116–143` sets cancellation then uses a completed-transfer metrics snapshot to decide if it can install attempt 1. The receiver checks cancellation at `exchange.rs:980–984`, may finish a no-clobber local persist, then updates the completion registry at `995–1003`. Once past its cancellation check, a receiver holding a complete in-flight old terminal can persist and register it after the recovery-side metrics snapshot. `worker.rs:775–788` sends the gather terminal before returning final task metrics. The resulting old terminal and new recovery episode can coexist inside the coordinator. The commit map still isolates attempts and prevents double collection, and the replacement independently validates replay manifests (`coordinator.rs:652–665`). No duplicate or incorrect returned row was observed.

**Fix and proof.** Give the Store a single terminal/abandoned transition mediated by its registry. A fully completed old transfer before abandonment refuses recovery; an abandoned old attempt never registers a completion. Keep filesystem I/O outside global locks or provide explicit bounded in-flight finalization, and preserve immutable transfer/attempt IDs and old wire format. Test an injected pause between final data validation and registry publication, a genuinely already completed terminal, and classic incomplete-prefix recovery. Retain real worker-loss and late-old-attempt tests as distinct proofs.

### ADE-IR-006 · P2 · high/source-supported · B — Resource-manager output read amplifies work with output size

**Contract and trace.** Phase 23 supplies tenant-authorized reads of immutable Phase 12 output. `ade-resource/src/service.rs:333–351` authenticates ownership, drops the manager lock before readback, and reauthenticates before reply. `ade-resource/src/native.rs:357–388` invokes full `ade_ops::runner::verify_output` each request, opens the pathname again and reads at most 12 KiB. `ade-ops/src/publication.rs:448–496` hashes the complete artifact, then reopens and decodes the complete stream. Downloading a result near 64 MiB at the maximum payload per request thus does roughly 5,462 full hash/decode operations. The upper illustrative logical read count for two full reads is about 683 GiB before buffering effects; this was derived, not measured. At every offset the returned bytes are read from a third file open. The trusted private-root contract excludes hostile replacement but there is no descriptor continuity across the verify/read seam.

**Fix and proof.** Extend the native verifier to return an owned, rewindable handle and proof. Consider a bounded per-result read session/token or a one-time opened verification cache bound to inode/metadata, exact job/proof and authorized principal, with reauthorization before every chunk. Keep directory trust, expiry and clear refusal on changed artifact or revoked tenant. First measure a deterministic read/decoder-byte counter across a multi-chunk output and concurrent cancellation/authorization controls. Do not weaken native digest or catch revocation with caller timing alone.

### ADE-IR-007 · P2 · high/source-supported · B — Cache wall-clock rollback can increase residual value and revive eligibility

**Contract and trace.** ADR-0033 policy and Phase 26 plan §5 say a rollback yields zero incumbent value. `ade-cache/src/policy.rs:77–99` only assigns zero before creation or at/after expiry. Within a horizon 100–200, observing 180 then 120 changes residual from one-fifth to four-fifths; no last accepted wall time exists in `store.rs:190–229`. The runtime hit path checks only `wall_ms() < expires_ms` at `669–671,705–731`. An uncollected expired entry can become hit-eligible again if the clock returns into its horizon. The additive remediation report narrower wording explicitly covers rollback *before creation*. Cache hits still perform original-source pre/post verification; this is TTL/placement truthfulness, not a stale-source bypass.

**Fix and proof.** Reconcile the plan/ADR with a clear clock contract. If all observed regressions must zero value and deny renewed eligibility, design a bounded monotonic time witness with safe reboot and crash semantics and explicit policy behavior under time uncertainty. If an operator-attested nondecreasing wall clock is the supported deployment restriction, state its exact limitation throughout and separately refuse observed pre-creation timestamps. Provide deterministic injected clock tests across creation, observation, over-expiry and backward re-entry, plus restart behavior for the selected contract. Avoid silently relying on a process monotonic clock across processes.

### ADE-IR-008 · P3 · high/source-supported · A — Cache exact subset has a tie-order mismatch

**Contract and trace.** ADR-0033 promises least displaced value, fewest freed bytes, then sorted key order. `ade-cache/src/policy.rs:229–243` summarizes each right-half bucket by tuple `(loss, bytes, numeric_bitmask)`, while outer comparison at `245–271` uses the lexicographic index vector. In one four-entry right half, the equal-cardinality sets `{0,3}` and `{1,2}` have masks 9 and 6. Assign sorted right keys and byte lengths `[1,2,4,5]`, equal loss 1, need 6 bytes, and four earlier entries with strictly greater loss. Both free exactly 6 at loss 2. The right bucket can retain `{1,2}` before the outer comparator sees the lexicographically earlier `{0,3}`. The selected value/capacity remains optimal. The offline Python oracle compares sorted keys as required (`scripts/phase26/verify.py:161–176`).

**Fix and proof.** Use one consistent lexicographic comparison in the bucket and across halves, retaining the bounded meet-in-the-middle algorithm. A small independently enumerated test covers this exact equal-byte/equal-loss case plus no-charge expired entries and equal candidate-value refusal. No new manifest or key format is needed.

### ADE-IR-009 · P2 · high/source-supported · B — Gateway ticket expiry leaves already-redeemed readers alive until transport closure

**Contract and trace.** The v1 guide gives 16 tickets for 15 seconds, 4 readers, zero spool. `ade-gateway/src/service.rs:129–141,390–423` removes expired ticket-map entries, but DoGet clones the frame Arc and stores the permit in a plain iterator. There is no per-stream expiry or idle release. `main.rs:77–88` applies a request timeout and 120 s connection age plus 15 s grace. The pinned Tonic transport timeout is a future over the response rather than a response-body timer. Thus a stalled reader may hold one of the four slots and its up-to-2-MiB retained frame set after ticket expiry, until flow resumes, client drops or the transport age/grace intervenes. Multiple already-redeemed old results can coexist with a fresh 16-entry ticket map. Explicit caps still bound the number of active streams, and stock clients request an 11 s timeout. The report already says stalled-reader recovery was unverified; this trace identifies the ownership gap behind that limitation.

**Fix and proof.** Use a body/stream lifetime and cleanup mechanism that works even when the transport stops polling the stream due to backpressure, or specify and separately account the accepted connection-level recovery interval. Make expiry semantics explicit for already initiated reads.
